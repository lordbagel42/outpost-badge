# Doom-on-badge port: session state (updated 2026-08-26)

Goal: run Doom natively on the badge's RP2354A driving the SSD1680 e-ink.

**Status: RUNNING.** Doom plays on the badge at ~9.4 fps, buttons work, and a
hold-L+R+A+B name-badge takeover ("kill Doom" → show my info) is implemented.
Remaining: on-hardware verification of the ghosting fix + badge art after the
panel is reconditioned; then strip debug instrumentation for a final clean build.

## What this is

A port of [kilograham/rp2040-doom](https://github.com/kilograham/rp2040-doom)
(branch `defcon32`, the RP2350 DEFCON 32 badge version) to the Outpost badge.
New display backend `src/pico/eink.c` replaces `lcd.c`; 6-button input with
chords in `src/pico/i_input.c`; board `boards/outpost_badge.h`.

## The original R_Init hard-fault — root cause (STATE.md's old guess was WRONG)

Old hypothesis (zone too small; raise RAM to 512k in `memmap_doom.ld`) was wrong
on every count: `memmap_doom.ld` is dead (unreferenced; build uses pico-sdk's
default RP2350 script), and the zone is capped at 256 KB by the short-pointer
scheme (`SHORTPTR_BASE=0x20030000`), not RAM size.

**Actual cause:** the committed `doom1.whx` was out of sync with the code's
vpatch enum — its `P_START` lump was 768 bytes (384 vpatches) but the firmware's
`NUM_VPATCHES`=385 (code added a leading `VPATCH_NAME_INVALID` after the whx was
generated). `R_InitSpriteLumps` hit `I_Error("whd is out of sync with VPATCH
enum")`, and under `NO_IERROR` `I_Error` is a bare `__breakpoint()` = silent hard
fault. **Fix:** rebuilt `whd_gen` from this tree and regenerated `doom1.whx` from
the authentic shareware `doom1.wad` (md5 f0cefca49926d00903cf57551d901abe) → 385
vpatches, matches.

## Build environment (Arch box, this machine)

Layout at `~/doom-badge/`: `pico-sdk`@2.1.1 (+tinyusb submodule), `pico-extras`
@master, `rp2040-doom`@defcon32 with `doom/doom-port.patch` applied
(`git apply --exclude='doom_outpost_*.uf2'`). Use the `.patch`, NOT
`apply_port.py` (which omits `hardware_spi` + the SPINLOCK defines).

Toolchain gotchas:
- System `arm-none-eabi-gcc` 14.2 has no newlib. Build with the self-contained
  Particle GCC-ARM 10.2.1: cmake `-DPICO_TOOLCHAIN_PATH=$HOME/.particle/toolchains/gcc-arm/10.2.1`.
- pico-sdk `tools/pioasm` needs `#include <cstdint>` in `pio_enums.h` for gcc14.
- host `whd_gen`: add `<cstdint>` to `src/whd_gen/wad.h`, `whd_gen.cpp`,
  `lodepng.cpp`; make `SDL2_net` non-REQUIRED + stub `SDL2::net` in top
  CMakeLists so the host build configures without SDL2_net.

Configure (usbdebug/dev variant):
```
cmake -GNinja -DCMAKE_BUILD_TYPE=MinSizeRel \
  -DPICO_TOOLCHAIN_PATH=$HOME/.particle/toolchains/gcc-arm/10.2.1 \
  -DPICO_SDK_PATH=$HOME/doom-badge/pico-sdk \
  -DPICO_EXTRAS_PATH=$HOME/doom-badge/pico-extras -DPICO_BOARD=outpost_badge \
  -DPICO_BOARD_HEADER_DIRS=$HOME/doom-badge/rp2040-doom/boards \
  -DHACK_ENABLE_STDIO_USB=1 ..
ninja doom_tiny
python3 pack2.py build-outpost-usb/src/doom_tiny.uf2 out.uf2   # from repo root; needs doom1.whx
```
The dev build's connect-wait is disabled (`PICO_STDIO_USB_CONNECT_WAIT_TIMEOUT_MS=0`)
so it boots Doom standalone; USB still enumerates for reflash/logs.

**WAD address:** `TINY_WAD_ADDR` moved from 0x10040000 → **0x10044000** because the
name-badge image (`badge_image.h`, 4736 B) grew code past the old 256 KB WAD
boundary (code+WAD overlapped → invalid image → bootloader rejected it). `pack2.py`
`base` must match. Code now ends ~0x10041300 (~11 KB headroom under 0x10044000).

## Features

- **Display:** 320x200 → 296x128, Bayer-dithered 1-bit, fast partial refresh via
  the custom short LUT (`0x22=0x0C` per frame reuses the loaded LUT). Waveform
  tpa=2 / groups=3 = 9.4 fps "milestone" contrast. +1.5x luma contrast-stretch
  before dither for clarity. `eink.c`.
- **Controls (`i_input.c`):** U/D/L/R move·turn, A=use, B=fire (A/B independent —
  no A+B menu chord). L+R=menu; in menus A=select. FN=hold U+D (strafe/weapon).
  Hold **U+R+A+B 3s** = full panel reset (ghost clear). Hold **L+R+A+B 3s** =
  toggle the name-badge takeover (debounced, tolerates <200ms bounces).
  **U+D+A+B** = reboot to BOOTSEL.
- **Name badge:** `badge_image.h` (296x128, generated by `doom/gen_badge.py`:
  avatar + Phantom Sans name + OUTPOST logo + HACK CLUB flag + Open Sauce logo).
  On toggle, `eink.c` does a strong 2-pass clear (black→white full refresh) then
  draws the badge; leaving badge mode clears again before resuming Doom (so
  neither ghosts into the other).

## Reflash loop (no manual BOOTSEL needed while firmware runs)

`python3` open the CDC port at 1200 baud → reboots to BOOTSEL; `udisksctl mount
-b /dev/sda1`; copy the packed UF2 to `/run/media/raygen/RP2350`; `sync`. Capture
logs: open /dev/ttyACM0 (DTR) with pyserial (`doom/capture.py`). Tools present:
`tio`, pyserial. Recover a ghosted panel: the CircuitPython recondition path in
`firmware/`.

## Debug instrumentation still in (strip for the final build)

`RDBG(...)` traces in `r_data_whd.c`; `[badge]` combo trace + swallow prints in
`i_input.c`; `I_Error` in `src/pico/i_system.c` changed to print + keep USB alive
(loop) instead of a silent breakpoint — worth KEEPING as recovery.
